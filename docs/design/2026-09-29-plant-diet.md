# 植物性饮食需求

> 状态：待确认 | 日期：2026-09-29 | 作者：奥恩 + AI (Grok 4.7)
> 确认流程：本文档经奥恩确认后才进入编码。本篇只规划需求，不写实现。

## 1. 目标与非目标

在 fde-agent 里增加「植物性饮食」场景，和工单诊断并列。这一版只做食材录入和列表。

一条食材只记这些：

- 名称
- 分类：蔬菜、水果、豆类、谷薯、坚果、植物奶、调味、冷冻
- 数量、单位
- 单价（手填），总价（自动计算）
- 购买日（默认当天）
- 保质期天数（手填），到期日（自动计算）

**不做**

- 存放位置、开封日、备注、过敏原、库存下限、用量扣减、浪费记录。
- 一周食谱、采购清单、营养素、条形码、对话。
- 本篇不实现代码，不改数据库。

## 2. 计算规则

- 总价 = 数量 × 单价。总价只读，改数量或单价时跟着变。
- 到期日 = 购买日 + 保质期天数。到期日只读，改购买日或保质期天数时跟着变。
- 例：2026-09-29 购买，保质期 7 天，到期日是 2026-10-06。
- 金额用人民币元展示，存储用分。数量允许小数（如 1.5 kg）。
- 单价允许 0。

单位：g、kg、ml、L、个、盒、袋、瓶。单价按所选单位计，例如单位是 kg 时，单价是每 kg 的价格。

同一种食物买两次，记两条。价格和到期日可以不同。

## 3. 这一版做什么

| 编号 | 需求 | 验收 |
|---|---|---|
| P1 | 录入 | 填完必填项后出现在列表里，总价和到期日是算出来的 |
| P2 | 修改、删除 | 改数量、单价、购买日、保质期天数后，总价和到期日重算；删除需确认 |
| P3 | 列表 | 按到期日从近到远；可按名称搜索，可按分类筛选 |
| P4 | 日期标签 | 到期日在 7 天内标「临期 N 天」；早于今天标「已过期」 |
| P5 | 金额 | 每条显示单价和总价；列表底部是全部总价之和 |
| P6 | 空与失败 | 没有食材时有空状态；保存失败时表单还在，并提示错误 |

## 4. 字段

| 字段 | 谁填 | 规则 |
|---|---|---|
| 名称 | 用户 | 必填，如「北豆腐」 |
| 分类 | 用户 | 必填，八类之一 |
| 数量 | 用户 | 必填，大于 0 |
| 单位 | 用户 | 必填 |
| 单价 | 用户 | 必填，元，≥ 0 |
| 总价 | 系统 | 数量 × 单价 |
| 购买日 | 用户 | 必填，打开表单时为今天 |
| 保质期天数 | 用户 | 必填，正整数 |
| 到期日 | 系统 | 购买日 + 保质期天数 |

## 5. 方案

食材放在 `packages/data` 的新表，和聊天、知识库分开。页面是 `apps/web` 的一个路由，侧边栏增加「植物性饮食」。不改 agent，不把食材放进向量库。

## 6. 交互规格

### 6.1 线框

```
┌──────────┬──────────────────────────────────────────┐
│ fae-agent│ 植物性饮食                    [+ 录入食材] │
│          │ 搜索名称          分类 ▾                   │
│ 对话     │                                          │
│ 植物性饮食│ 北豆腐                         临期 2 天  │
│          │ 豆类 · 400 g                             │
│          │ 单价 ¥0.02/g · 总价 ¥8.00                │
│          │ 购买 09-29 · 保质期 7 天 · 到期 10-06     │
│          │                        [编辑] [删除]      │
│          │                                          │
│          │ 共 1 条 · 总价 ¥8.00                      │
└──────────┴──────────────────────────────────────────┘

录入：

  名称 [          ]
  分类 [豆类 ▾]
  数量 [400] [g ▾]
  单价 [0.02] 元          总价 ¥8.00
  购买日 [2026-09-29]
  保质期 [7] 天           到期 2026-10-06
  [取消]  [保存]
```

### 6.2 状态

| 视图 | 样子 |
|---|---|
| 空 | 「还没有食材」，按钮「录入食材」 |
| 加载 | 「正在加载」 |
| 有数据 | 卡片列表，底部是条数和总价之和 |
| 筛选无结果 | 「没有符合的食材」，可清除筛选 |
| 保存中 | 保存按钮不可再点 |
| 保存失败 | 表单不关，已填内容还在，顶部一行错误 |
| 临期 / 已过期 | 卡片上的标签，列表本身不过滤掉它们 |

### 6.3 交互

| 动作 | 反馈 |
|---|---|
| 打开页面 | 按到期日从近到远列出全部食材 |
| 点「录入食材」 | 空表单，购买日为今天，总价和到期日随输入变化 |
| 必填没填就保存 | 标出缺的字段，不发请求 |
| 数量 ≤ 0，或保质期天数不是正整数，或单价 < 0 | 标出该字段，不发请求 |
| 保存成功 | 表单关闭，列表出现新条目，底部总价更新 |
| 编辑 | 表单带出原值；保存后总价和到期日按新值重算 |
| 删除 | 先确认；确认后从列表消失 |
| 搜索 / 分类筛选 | 只改当前列表 |
| 请求失败或超时 | 表单保留，提示「没有保存，请再试一次」 |
| 连续点保存 | 第一次点击后按钮禁用，直到成功或失败 |

Interview · Agent 0→1

企业要的不是另一个聊天框。
要的是一段岗位流程被做成智能体。

我独立完成过一条从 0 到 1 的路径：定场景、写设计、编码、接到知识库和办公软件、自己验收。下面用一个真实项目说明我能交付什么，以及我怎么回答你们的追问。

人确认关键节点 · AI 写草稿

01 · 交付物

我做成的东西：fde-agent

给一线交付人员用的智能体工作台。知识库提供依据，人确认关键稿，模型可以换，本地也能跑。

网页

会话、流式回答、售前表单、方案卡、底部运行日志。

命令行

同一套能力进终端，方便实施和排障。

飞书 / 企微

群里或应用里收消息，走同一套诊断或问答，再把文字发回去。

02 · 一个能演示的闭环

售前方案：三步，中间必须人改

表 A客户名称、行业、痛点、场景。必填，前端先挡住空表。
→
AI 画布8 个方案字段的草稿，依据来自知识库。
→
人确认交付人员改完全部字段，再放行。
→
6 段整案需求理解、机会、方案、Demo、风险、待补信息。

关掉「模型反复追问」。缺信息在表单里收齐，不靠聊天碰运气。

03 · 第二个场景

工单诊断：有结构，有引用

输入

一段工单描述。机器人里以「诊断：」开头即可走这条路径。

输出

问题定位、根因、解决方案、预防措施、置信度，并带上知识库引用。

为什么要两个场景

场景是可插拔的：聊天、诊断、售前共用会话和知识库，各自有提示词和输出格式。再加一个业务，是登记一份场景定义，不是重做产品。

04 · 架构（一张图讲完）

一个进程里的工作台，模型通道可换

人（网页 / 命令行 / 飞书企微） │ ▼ 接入层 同一套会话与知识库 │ ▼ 智能体运行时 场景：聊天 · 诊断 · 售前 │ ├── 知识库检索（文档先切片、再向量） └── 模型通道：云 API，或本机 Claude / Cursor CLI

日常开发通常只有 1 个 Web 进程。选本机 CLI 时，这一轮请求再临时拉起一个子进程，结束就退出。

05 · 0→1 里我做过的判断

四个我会在面试里展开的决定

先定人机边界

售前终稿前必须有人改画布。AI 负责草稿和检索，不负责拍板。

模型通道抽象

业务代码不绑死一家。云 API 与本机订阅 CLI 同一接口。Cursor 走只读问答，避免机器人改文件。

知识库按文档形态切

普通文本按段落约 500 字；手册按标题切，表格尽量整块，避免把参数表拦腰截断。

办公软件只做皮肤

飞书、企微负责验签、解密、收发。脑子仍是同一套智能体。群聊默认要 @ 才回。

06 · 他们一定会问的 RAG

依据从哪来，错了怎么查

环节做法我怎么讲边界
入库文档切片后做向量，写入本地库切片策略按文档类型选，不一种切法打天下
提问先检索再交给模型；售前会用多条查询合并检索不到就明确说证据不足
排障关键路径打标签日志，网页底部可看例如中文键被映射、检索命中几条，不用猜

07 · 我怎么带 AI 写代码

设计先写下来，你说可以，我才改代码

设计目标、不做什么、接口、影响面。
→
人确认口径变了先改文档。
→
编码类型放共享包，密钥只走环境变量。
→
真跑调一次接口或点一次界面，再看类型检查。

Cursor、Claude Code、Codex 共用同一份规范。规范若各写一份，三天后就会漂。

08 · 我不夸大的部分

现在适合试点，还不是集团级中台

单机数据

嵌入式数据库，零外部服务，方便私有化试用。多实例同时写会抢锁。上生产要换正式数据库。

没有权限和计费

面向内部交付人员。多租户、审计、配额是下一阶段，不是已经做好。

评测还轻

靠真实调用、类型和关键路径冒烟。上线前要补业务评测集和人工抽检。

09 · 如果加入贵司

先选一条岗位流程，
90 天做出能演示的闭环。

前 2 周

选场景，画人机边界：哪一步必须人工确认。摸清文档在哪。

中间

知识库、结构化输出、一个入口（网页或飞书）。每周给用人部门看一版真跑。

收尾

日志、失败样本、一份「不能做什么」清单。再决定要不要扩第二个场景。

备答 · 不要主动念

追问时翻后面几页

和扣子 / Dify / Coze 比

它们是平台。我展示的是：选定一个岗位流程后，怎么把人机边界、检索、办公软件和验收做完。

数据出不出公司

库在本地。走云模型时，提示词会出网，这点必须先和安全说清楚。也可改走内网模型或本机 CLI。

你写还是 AI 写

判断、确认、验收是我。AI 加速实现。提交有类型和规范门禁，编译通过不算完成。

失败例子

模型曾把字段写成中文键，解析失败。后来做了键名归一，并在日志里打出映射了几项。

备答

为什么不直接用现成智能体平台？

平台适合快速拼流程。我这份工作证明的是：当流程要嵌进你们的知识、确认权和办公软件时，我能从零把运行时、数据、入口和验收接起来，而不是只会拖拽节点。

避免说「那些平台不行」。可以说「试点可以先用平台，核心流程我要能讲清数据怎么走」。

备答

客户资料会不会上传到公有云？

会话和知识库默认在我们自己的机器上。若选用云端模型，当次提示词会发到该供应商。上线前要定：内网模型、本机 CLI，还是允许出网。密钥只放环境变量，日志不打全文和密钥。

不要承诺「绝对不出网」，除非对方指定内网模型并且你验证过。

备答

模型胡说怎么办？

三层：检索不到就说证据不足；结构化输出对字段；关键稿必须人改完再进入下一步。售前的 6 段整案发生在画布确认之后。另外用日志看它检索到了什么、解析有没有改写字段。

不要说「我们的模型不会幻觉」。

备答

成本怎么控？

云 API 按调用付费，本机 Claude / Cursor 走已有订阅。架构上可以按场景换通道：对内试用用订阅，对客户正式调用再用可审计的 API。我还没有做配额和账单，那是上生产前要补的。

备答

能不能给全公司用？

现在适合一个团队试点。数据层是嵌入式库，方便零依赖启动，不适合多实例并发写。要全公司用，我会换正式数据库、加登录和权限，机器人与网页继续共用同一套场景。这是迁移，不是推倒。

备答

你在团队里站哪一岗？

我能独立把一个场景从问题定义做到可演示：和业务定确认点、设计数据流、实现检索和入口、自己做冒烟。团队里我适合应用负责人或智能体工程师，旁边需要业务负责人口径，安全负责出网策略。我不把自己说成算法研究员。
